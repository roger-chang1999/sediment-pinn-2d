## 分析討論（關卡二，可多輪）

### 初步報告（④-1，2026-11-07）
- 結果 vs 預測：#1 不符（第一階段未下降）；#2 違反預測，遠優於預期；#3 方向符合；#4 正算符合、反算 K 失敗；#5 正算不符。
- 實作與原文的偏差（子代理讀 arXiv HTML 全文，部分附錄只有摘要）：因果訓練把 IC 計入累積和、未做 ε 退火（原文 Eq. 3.2 從 k=1 起、ε 依 [1e-2…1e2] 退火）；我們的 gradnorm 公式對應 Wang 2023 *Expert's guide*（2308.08468）Eq. 2.12–2.15，不是 wang2021 的 max/mean 版；SOAP 為簡化版，超參數與 Wang 2025 不同（他們搭配 gradnorm 與因果訓練、PirateNet）。
- 異常 A：反算第二階段幾乎沒跑。異常 B：SOAP 反算 obs loss 1.5e-6（base 2.1e-4），疑似擬合雜訊、K 被壓小（推測）。
- 不能推論：因果訓練無效（實作偏離）、gradnorm 本身很強（可能是固定權重不好）、BFGS 變體較差（單一實作）、SOAP 不適合反算（可能是組合問題）。
- 流程問題：Claude 在初步報告中就提出下一步 node 選項；使用者指出應在結論形成後才提，促成 epistemic-provenance v0.5（關卡二改為多輪）。

### 第 1 輪（2026-11-08）：異常 A，反算第二階段為什麼停
- 診斷 1（使用者同意）：從 base 第一階段存檔重跑反算第二階段，記錄停止原因。
  - 3 個 seed 都是**線搜尋失敗**（最後步長 t=0，觸發「步長太小」條件），不是收斂；停止時最大梯度 8e-4–2e-3（收斂門檻 1e-7）。
  - 起點 loss 組成（含權重）：obs 1.2e-2–2.1e-2，占總 loss 約 96–98%；pde 1.6e-5–6.3e-5。K、ws 的梯度約 1e-6。
- 使用者的解讀：「如果採取 gradnorm，就能重新讓 L-BFGS 開始訓練。」
- Claude 的補充：gradnorm 組的第一階段也不同，起點與權重兩個因素混在一起；正算 base seed 2 沒有 obs 也停了，是反例。
- 診斷 2（使用者同意）：
  - (a) **起點不變**（base 第一階段存檔），第二階段權重改用 gradnorm 公式在起點算一次後凍結（`--stage2-weights gradnorm`）：

    | seed | L-BFGS 步數／停止原因 | relL2 第一階段 → 最終 | K 第一階段 → 最終 | 第二階段權重（pde, ic, bc, obs） |
    |---|---|---|---|---|
    | 0 | 500／達上限 | 4.74 → **1.30** | 1.850 → 1.893 | 26.5, 1.4, 120, 3.9 |
    | 1 | 341／步長太小 | 4.28 → **1.59** | 1.636 → 1.959 | 8.0, 1.9, 31.6, 3.2 |
    | 2 | 500／達上限 | 7.87 → **4.50** | 1.464 → 1.514 | 1.4, 11.5, 12.4, 10.4 |

    對照：完整 gradnorm（第一階段也用）最終 0.75／0.59／2.54%、K 1.936／2.032／2.059。
  - (b) 正算 base seed 2 第二階段：3 步、步長太小（t=0.0054），起點 pde 2.9e-3 為主，relL2 83.6% 不變；沒有 obs 也發生線搜尋失敗。
- Claude 的初步整理：(1) 反算 base 第二階段停住的主因是權重；(2) gradnorm 的好處同時來自兩個階段（起點也有影響）；(3) 線搜尋失敗另有與權重無關的機制。
- **使用者指出 (2) 的推論有問題**：比較的雙方都在固定步數下停止（(a) 的 seed 0、2 撞到 500 步上限，完整 gradnorm 也只跑 364／483／500 步），差距可能只是步數不夠、尚未收斂。Claude 同意並撤回 (2)；同樣的限制適用於整批消融（每個數字都是固定預算下量的）。
- 收斂判定的討論：
  - 使用者同意「線搜尋失敗是卡住，不是收斂」。
  - 使用者提議用 patience；Claude 建議監看訓練 loss（不用 relL2，真實資料沒有正確答案）、相對改善 1e-4、patience 300、上限 5000 步，K 的漂移只報告不作停止條件。
  - 使用者提醒 patience 和學習率排程可能衝突。共識：第二階段 L-BFGS 沒有排程（線搜尋決定步長）、固定配點、權重凍結，所以 patience 判斷乾淨；第一階段（Adam 排程綁定總步數、每步重抽配點、gradnorm 改變 loss 尺度）則不適用。
- 使用者的觀點：第一階段像 pretrain，不需要比較第一階段的指標，重點是最終收斂結果。Claude 的修正：兩階段的 loss 相同，物理約束在第一階段就有；「不必比較」不等於「不重要」，起點會不會影響收斂後的解，正是診斷 3 要回答的。
- 使用者的觀察：「第一階段的 PDE loss 相對真實資料的數量級很小，幾乎等於沒加。」Claude 的補充：
  - 要看梯度貢獻而非 loss 數值（loss 小也可能是已被滿足）。由診斷 2(a) 的 gradnorm 權重（λ_k ∝ 1/‖∇L_k‖）反推，base 權重下第一階段結束時 PDE : obs 的梯度貢獻約為 1:680、1:250、1:13（seed 0／1／2）。使用者的觀察在 seed 0、1 成立，seed 2 較弱；訓練初期未記錄。
  - 這是權重問題而非階段問題：base 兩階段權重相同；正算沒有 obs，PDE 是主要 loss。
- **共識**（使用者接受）：
  - 反算 base 中，固定權重 obs 100 讓 PDE 的梯度貢獻降到千分之幾，兩個階段都一樣；這是 K 梯度 ~1e-6、L-BFGS 線搜尋失敗的背景。
  - 只換第二階段權重就能讓 L-BFGS 重新運作（3/3 seed）。
  - 評估重點是收斂後的最終結果；第一階段指標不需比較，但第一階段的選擇是否影響最終解仍待診斷 3。
  - 固定權重 obs 100（Claude 未經討論訂定）是混淆變因，可能本來就不適合反算。
- 診斷 3（使用者同意，執行中）：第二階段 L-BFGS 加 patience（300、相對 1e-4、上限 5000），對象為「base 起點＋第二階段 gradnorm 權重」與「完整 gradnorm」各 3 個 seed；結果在 `results/diag_stage2_patience/`。分段檢查與一次跑完在 60 步時逐位相同。
- 審查：未選擇

#### 第 2 輪（2026-11-08）：診斷 3 的結果（第二階段加 patience）
- 使用者要求定期查看，擔心 patience 觸發不了造成浪費。實際：6 個 run 共約 6 分鐘；1 個撞到 5000 步上限（202 秒）。

  | run | 停止狀態 | 步數 | K 起點 → 終點 | relL2 起點 → 終點 |
  |---|---|---|---|---|
  | 換權重 s0 | stopped(tolerance_change) | 572 | 1.850 → 1.901 | 4.74 → 1.33% |
  | 換權重 s1 | stuck(line_search) | 341 | 1.636 → 1.959 | 4.28 → 1.59% |
  | 換權重 s2 | not_converged(max_iter) | 5000 | 1.464 → **0.162** | 7.87 → **8.42%**（最低 4.10%，第 2060 步） |
  | 完整 gradnorm s0 | stopped(tolerance_change) | 364 | 1.538 → 1.936 | 2.29 → 0.75% |
  | 完整 gradnorm s1 | stopped(tolerance_change) | 483 | 0.530 → 2.032 | 5.42 → 0.59% |
  | 完整 gradnorm s2 | stopped(tolerance_change) | 1785 | 0.390 → 1.973 | 5.39 → 2.48% |

  軌跡圖：`results/diag_stage2_patience/trajectories.png`。
- 觀察：
  1. 完整 gradnorm 3/3 的 K 在第 100–500 步被拉到 1.94–2.03（起點 0.39–1.54）。
  2. 換權重 s2：約第 2000 步後 loss 急降、K 從 1.55 崩到 0.16、relL2 反轉變差——**loss 越低，參數越錯**（該 run 的第二階段權重 pde 1.4、obs 10.4）。
  3. 沒有 run 因 patience 停止；5 個為 torch 的 loss 變化 < 1e-9（float32 精度極限），4 個在最後 300 步 K 仍漂移 0.2–0.35。
- Claude 自我修正：兩組的第二階段權重值也不同（完整 gradnorm 用第一階段最後的權重；換權重組在 base 終點重算），「起點是否影響」仍混著權重，診斷 3 的設計有漏洞。
- Claude 的解讀（推測）：觀測權重相對 PDE 過高時，目標函數的最小值不在真值附近，L-BFGS 越精確優化就越精確擬合雜訊；SOAP 反算可能是同一機制。核心是「loss 的組成決定解在哪裡」，而不是優化器。
- 使用者的解讀：使用 gradnorm 的情況都成功收斂、K 都擬合回來，提議以「第一階段 Adam、第二階段 gradnorm L-BFGS」為方法。
- Claude 的修正：成功的是**完整 gradnorm**（第一階段 Adam + gradnorm → 第二階段 L-BFGS 沿用凍結權重）；只在第二階段用 gradnorm 的 seed 2 失敗。使用者接受。
- 共識：新基準為完整 gradnorm；「收斂」應精確寫為「K 已回收，但停止原因是 float32 精度極限，非 patience」。
