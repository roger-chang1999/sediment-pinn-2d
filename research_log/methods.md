# 評估方法登記表：這個專案用過哪些「評估 PINN 解」的協定

這個檔案回答「這個數字是怎麼量出來的」。它不放實驗結果本身（結果在 `experiments/`、`ideas/`），只放**量測方法**的定義、彼此的差異，以及各自回答什麼問題。

它和 `README.md` 一樣是中樞參考檔。每次要引用或比較數字前，先確認是不是同一種協定量出來的。

## 為什麼需要這份文件

同一個訓練好的網路，用不同協定量，數字可以差很多。例如 P0 正算 Adam 基準：第一階段（Adam）結束時 relL2 約 73%，接 L-BFGS 後是 2.6%，兩個數字都叫「relL2」。又例如 SGD+momentum 崩到 C≡0 時，PDE loss 是 10⁻²⁰（看起來「完美」），relL2 卻是 100%。混用就會誤判。

---

## 協定一：網格 relL2（只適用有解析解的 P0）

**回答的問題**：整個時空域裡，PINN 解和真值差多少？這是 P0 **預設的比較基準**。

**Recipe**（`experiments/p0_analytic.py` 的 `rel_l2()`）：
1. 空間網格 201 × 81（x ∈ [0,1000] m、y ∈ [0,400] m），時間取 t = 0, 50, …, 500 s 共 11 個時刻。
2. relL2 = sqrt( Σ(C_PINN − C_exact)² / Σ C_exact² )，所有時刻合併計算（不是各時刻分開再平均）。

**兩個版本，不能混用**：
- `relL2_stage1`：第一階段（Adam/SGD）結束、**L-BFGS 之前**。回答「這個一階優化器本身做到哪裡」。
- `relL2`：**L-BFGS 之後**的最終值。回答「整條訓練流程的最終品質」。
- L-BFGS 會大幅改變結果（Adam 73% → 2.6%），所以**比較優化器時兩個都要列**。只看最終值，會把「L-BFGS 救回來的部分」算成第一階段優化器的功勞。

**已知限制**：
- 誤差集中在泥砂團附近；遠離泥砂團的大片 C≈0 區域會稀釋分子和分母，所以 relL2 對「尖峰位置偏移」很敏感，對背景小誤差不敏感。
- 舊版結果（`net_legacy.pt` 那幾組中的 `p0_forward_adam_lr0.001`、`p0_inverse_adam_lr0.001`）**沒有記錄 `relL2_stage1`**。它們的「第一階段約 73%」取自訓練 log 第 14000 步的值，不是第 15000 步的精確值。

## 協定二：全域質量守恆誤差

**回答的問題**：PINN 解的總泥砂量 ∫ h C dA，是否照理論隨沉降衰減？

**Recipe**（`sscpinn/physics.py` 的 `total_mass()`）：
1. 矩形域中點積分，200 × 200 格。
2. 取 t = 0, 20, …, 500 s 共 26 個時刻。
3. 理論值 M(t) = M₀ · exp(−α_d w_s t / h)，其中 M₀ = h · C₀ · 2π σ₀²（**無限域**積分）。
4. 報告 max_t |M_PINN − M_exact| / M_exact。

**常見陷阱**：
- 理論值用無限域積分，計算域是有限的。t = 500 s 時泥砂團中心在 x = 750 m、σ ≈ 75 m，離下游邊界約 3.3σ，截斷誤差很小但不是 0。
- 理論 M(t) 一律用**真值** w_s。反算模式下，就算 PINN 自己估的 w_s 有偏差，也是拿真值比較，所以這個指標同時反映「場的誤差」和「參數的誤差」。
- 質量誤差和 relL2 不一定同方向：一個平移錯位的泥砂團，質量可以完全正確，relL2 卻很大。

## 協定三：參數反算誤差（只適用 inverse 模式）

**回答的問題**：從稀疏觀測能否找回 K、w_s？

**Recipe**：K、w_s 以 log 參數化（保證為正），從錯誤初值出發（K₀ = 0.5、真值 2.0；w_s,0 = 5×10⁻³、真值 1×10⁻³），與網路權重一起訓練。報告 `K_est`、`ws_est`，以及第一階段後的 `K_stage1`、`ws_stage1`。

**合成觀測**：6 個測站 × 40 個時刻，5% 相對高斯雜訊（乘法雜訊，再截斷為非負），雜訊由 seed 決定。

**常見陷阱**：
- 單一 seed 的點估計**沒有不確定度**。「K = 1.91」不代表信賴區間；要談不確定度，需要多 seed 或 bootstrap，見 [ideas/005](ideas/005-inverse-as-calibration-and-statistics.md)。
- 參數停在初值不一定是「找不到」，也可能是梯度消失。例如 SGD+momentum 崩到 C≡0 時，K、w_s 完全停在 0.5、5×10⁻³。要搭配 loss 分項一起看。

## 協定四：訓練 loss 分項（過程指標，不是品質指標）

**回答的問題**：訓練是否在正常進行？哪一項卡住了？

**Recipe**：每步記錄 `pde`、`ic`、`bc`、`obs`（反算才有）和加權後的 `total`。
- `pde = mean[(R_C / R_ref)²]`，R_ref = h·C₀·U/σ₀ ≈ 0.033 kg/(m²·s)
- `ic`、`bc`、`obs` 都除以 C₀ 正規化
- 權重：pde = 1、ic = 100、bc = 10、obs = 100

**常見陷阱（已經踩過）**：
- **PDE loss 小 ≠ 解正確**。C≡0 讓 PDE 殘差 ≈ 10⁻²⁰（見 [ideas/003](ideas/003-pde-loss-small-not-correct.md)）。判斷訓練成敗時，**一定要同時看 `ic`（和 `obs`）**。
- 第一階段每步都重抽 PDE 配點和 BC 點，所以 loss 曲線本身帶抽樣雜訊；L-BFGS 階段改用固定配點。兩階段的 loss 數值不能直接比。
- 換了 loss 權重（例如之後的自動權重實驗），`total` 就不可比，只能比各分項或協定一。

## 協定五：訓練時間

**Recipe**：`train_time_s` 包含第一階段和 L-BFGS，**也包含每 1000 步的 relL2 評估開銷**。

**常見陷阱**：
- 2026-11-06 的 AdamW wd=1e-4 那組（372 s），執行期間 GPU 同時在跑 checkpoint 測試，**時間不可比**。其他幾組也可能有部分重疊。要比較計算成本，必須在 GPU 獨占時重跑。

## 協定六：第二階段停止狀態（2026-11-08 起）

**回答的問題**：L-BFGS 停下來時，是收斂、卡住，還是預算用完？

**Recipe**（`--s2-patience` 模式）：每 10 步檢查一次訓練 loss（加權總 loss，固定配點）；相對改善 > 1e-4 才算改善；連續 300 步無改善即停；上限 5000 步。停止狀態：
- `converged(patience)`：收斂
- `stuck(line_search)`：線搜尋失敗（t=0），是**卡住**不是收斂（使用者確認）
- `stopped(tolerance_change)`：torch 判定 loss 或步長變化 < 1e-9；float32 下多半是精度極限，**不等於收斂**
- `not_converged(max_iter)`：撞到上限

另記錄軌跡（loss、K、ws、relL2）與最後一個 patience 窗口內 K 的漂移。不用 relL2 當停止條件（真實資料沒有正確答案）。非 patience 模式也會記錄停止原因與起點 loss 組成。

**陷阱**：
- patience 只適用第二階段（無學習率排程、固定配點、權重凍結）。第一階段的學習率排程綁定總步數、每步重抽配點、gradnorm 會改變 loss 尺度，直接套 patience 會誤判。
- 分段呼叫 torch L-BFGS 時要取消每段的 `max_eval` 上限，否則會被誤判為卡住。
- **固定預算的數字只代表預算內的表現**（[exp-p0-training-improvements-ablation](experiments/exp-p0-training-improvements-ablation.md)）。

## 協定版本變更紀錄（重要：跨版本的數字不能直接比）

| 版本 | 日期 | 變更 | 影響 |
|---|---|---|---|
| v1 | 2026-11-05～06 | IC 取樣點、觀測雜訊用**全域亂數**，在網路初始化之後產生 | 結果在 `results/_legacy_v1/`。改網路結構（例如 Fourier features）會改變同 seed 的資料 |
| v2 | 2026-11-07 起 | IC 取樣點、觀測雜訊改用**獨立亂數產生器**（seed + 1000）。同一 seed 下所有方法看到的資料完全相同；新增 `relL2_stage1`、`relL2_stage1_per_time`、`relL2_per_time`（每個時刻各自的 relL2）、`snapshots_stage1.png`、第一階段與第二階段分開計時 | v1 和 v2 同為「seed 0」，但資料不同，**是不同的實驗**。比較時只用同版本 |

v2 的因果訓練記錄的 `pde` loss 是**加權後**的值（Σ w_i·L_i / N_t），和沒開因果訓練時的 `pde` 不可比；比較時以協定一為準。

## 規劃中的協定（P1 以後，來自原始構想）

| 層次 | 指標 | 說明 |
|---|---|---|
| 測站 SSC | RMSE、MAE、偏差、R²、NSE | 洪峰和低濃度期分開看 |
| 斷面輸砂率 | Qs(t) 歷線、峰值時間、峰值偏差 | Qs = ∫Γ hC(u·n) ds |
| 事件累積量 | Ms 相對誤差 | Ms = ∫ Qs dt |
| 物理品質 | PDE 殘差、全域/分區質量收支 | 殘差需要歸一化 |
| 泛化 | 未參與訓練的洪水事件 | 依事件切分，不可把同一事件的時序隨機拆成訓練和測試 |

## 速查表：同一個網路，不同協定量到的東西

| 協定 | 需要真值？ | 量什麼 | 主要陷阱 |
|---|---|---|---|
| ① 網格 relL2 | 要（只有 P0） | 整個場的誤差 | stage1 和 final 不可混用 |
| ② 質量守恆誤差 | 要（理論 M(t)） | 積分量是否守恆 | 平移錯位不會被偵測 |
| ③ 參數反算誤差 | 要（真值參數） | 可識別性 | 單 seed 沒有不確定度 |
| ④ loss 分項 | 不用 | 訓練過程 | PDE loss 小 ≠ 正確 |
| ⑤ 訓練時間 | 不用 | 計算成本 | GPU 共用時不可比 |

**下結論前先確認**：比較表上的 relL2 如果沒有特別註明，預設是**協定一的最終值（L-BFGS 後）**。比較優化器時，必須同時列出 `relL2_stage1`。
